## Two things you must set before running

**1. `PYTHONPATH`.** The package is never installed — `setup.py` exists but
`pip install -e .` was not run — so `python -m eisoptx.main` fails with
`ModuleNotFoundError: No module named 'eisoptx'` even from the repo root,
because the interpreter's `sys.path[0]` is not the CWD under `-m` in this
layout. Fix:

```bash
export PYTHONPATH=/home/rcp756/code/generalized-aberrations
```

**2. OpenMP affinity guard.** This sandbox denies `pthread_setaffinity_np()`,
and the OpenMP runtime shipped with torch aborts with `OMP Error #179` rather
than degrading. Must be set *before* the process starts:

```bash
export KMP_AFFINITY=disabled OMP_PROC_BIND=false KMP_INIT_AT_FORK=FALSE OMP_NUM_THREADS=4
```

This is a property of the container, not of eisoptx. On a normal workstation
neither export is needed except `PYTHONPATH`.

## Verified working commands

```bash
python -m eisoptx.main test -c configs/toy/defaults.yml -c configs/toy/designs/optimized_spot.yml
python -m eisoptx.main fit  -c configs/toy/defaults.yml -c configs/toy/designs/optimized_spot.yml \
       --trainer.max_steps=3 --trainer.logger=null --trainer.callbacks=null \
       --trainer.enable_checkpointing=false
```

Both complete. The `test` command takes well under a minute on CPU; `fit` runs
at roughly 4.6 LM steps/s on the toy.

## Repository hygiene

Running the CLI writes into the repo:

- `logs/logs_ablation/s-aRa-aRa-/version_N/` — from the toy `test`/`fit` runs
  (the toy config points its logger at `logs/logs_ablation`).
- `logs/s-aRa-aRa-aRa-aRa-/version_N/` — from the `demo_tele4p` run.
- `lightning_logs/` — created at the repo root when `--trainer.logger=null` is
  passed, because Lightning falls back to its default logger directory. This
  one is **not** in `.gitignore` and shows up as untracked in `git status`.

None of this touches tracked source. To keep instrumentation out of the way,
`instrument_trace.py` builds its objects directly rather than going through the
Lightning trainer, so it writes nothing except its own dump files.

## Empty file worth knowing about

`configs/toy/designs/starting_point.yml` is **0 bytes**. The other two toy
designs are ~1.09 kB each. So the README's toy instructions that reference a
starting point have no starting design to load in this release — the toy
`defaults.yml` carries its own initial `c`/`s`/`a` values inline instead, and
those are the actual starting point. Worth flagging in the config chapter.
